# HealthMate 后端进展与待办（2026-04-26）

## 本次已完成

### 1. SSE 鉴权与建议流

- 已支持浏览器原生 `EventSource` 使用 query token：
  - `GET /api/advice/stream?token=...`
  - `GET /api/health/daily-report?token=...`
- `Authorization: Bearer <token>` 仍然可用。
- 已把建议流生成逻辑抽成可复用函数，`/advice/stream` 和 `/health/daily-report` 共用同一套逻辑。
- 已修正 SSE `tasks` 事件的数据格式，任务列表现在输出为合法 JSON 字符串。
- 已添加 SSE 响应头：
  - `Cache-Control: no-cache`
  - `X-Accel-Buffering: no`

### 2. 文档接口兼容别名

在保留当前前端主路径的同时，补齐了一批系统设计说明书中的接口路径：

- 用户接口：
  - `POST /api/user/register`
  - `POST /api/user/login`
  - `POST /api/user/profile/create`
  - `PUT /api/user/profile/update`
  - `PUT /api/user/goal/change`
- 健康记录接口：
  - `POST /api/health/record/natural`
  - `POST /api/health/record/confirm`
  - `POST /api/health/record/manual`
  - `GET /api/health/record/recent`
  - `GET /api/health/daily-report`
- 可视化接口：
  - `GET /api/visual/dashboard`
  - `GET /api/visual/trend`
  - `GET /api/visual/tags`
- 任务接口：
  - `GET /api/task/today`

### 3. 健康记录幂等与任务去重

- 健康记录提交改为按 `user_id + record_date` 幂等更新，避免同一天重复提交产生多条重复记录。
- 每日任务生成改为按 `user_id + task_date + task_content` 去重，同一天重复生成建议时不会重复插入相同任务。
- ORM 中补充唯一约束：
  - `t_health_record`: `user_id + record_date`
  - `t_daily_task`: `user_id + task_date + task_content`
  - `t_health_summary`: `user_id + summary_cycle + summary_date`

### 4. LLM Provider 兜底实现

- `LLMAdviceProvider` 已从占位实现改为 OpenAI-compatible Chat Completions 调用。
- 新增配置项：
  - `LLM_API_BASE`
  - `LLM_API_KEY`
  - `LLM_MODEL`
  - `LLM_TIMEOUT_SECONDS`
- 未配置密钥、接口异常、超时、响应解析失败时，自动回退到 `MockAdviceProvider`，保证演示可用。
- AI 建议上下文已增强，当前会组装：
  - 用户健康目标与目标版本
  - 伤病史/过敏史
  - 近 7 天健康记录
  - 最新周总结
  - 昨日任务完成率
  - 断签天数

### 5. 长期记忆、缓存与后台任务

- 已新增 `SummaryRepository` 与 `SummaryService`。
- 已支持生成并查询健康总结：
  - `POST /api/health/summary/generate`
  - `GET /api/health/summary/latest`
- 已新增可选缓存层：
  - 配置 `REDIS_URL` 时使用 Redis。
  - 未配置或 Redis 不可用时，自动使用进程内内存缓存。
- 已新增后台维护服务与受 JWT 保护的管理接口：
  - `POST /api/admin/jobs/archive-tasks`
  - `POST /api/admin/jobs/weekly-summary`
  - `POST /api/admin/jobs/pre-generate-advice`
  - `POST /api/admin/jobs/run-daily`
- 当前尚未引入 Celery，但这些接口可以直接被 Celery/APScheduler/系统 cron 调用。

### 6. 导出与字段兼容

- `GET /api/health/export` 支持：
  - `startDate`
  - `endDate`
  - UTF-8 BOM，便于 Excel 正确打开中文。
- 健康数据入参增加字段别名兼容：
  - `intakeCalories` / `intakeKcal` / `estimatedIntakeKcal`
  - `exerciseCalories` / `burnKcal` / `estimatedBurnKcal`
  - `tags` / `healthTags`
- 档案入参增加 `goal` 与 `healthGoal` 兼容。

### 7. 文档更新

- 已更新 `backend/README.md`，记录兼容接口与 LLM 配置方式。
- 已更新 `backend/TODO.md`，补充 2026-04-26 的后端进展。

### 8. 已验证

- 已运行语法编译检查：
  - `python -m compileall backend\app backend\tests -q`
  - 结果：通过。
- 已尝试运行测试：

## 2026-04-26 第二轮实现补充

### 本轮新增完成内容

1. 健康总结与长期记忆
   - 新增 `SummaryRepository`，支持按用户、周期、日期查询和 upsert 健康总结。
   - 新增 `SummaryService`，可根据指定日期范围的健康记录生成 200 字以内总结。
   - 新增用户侧接口：
     - `GET /api/health/summary/latest`
     - `POST /api/health/summary/generate`
   - `t_health_summary` 不再只是空模型，已经有业务写入和读取路径。

2. AI 建议上下文增强
   - 建议生成上下文已从“完成率 + 平均睡眠”扩展为：
     - 当前日期
     - 用户健康目标
     - 健康目标版本时间
     - 伤病史/过敏史
     - 近 7 天健康记录
     - 最新周总结
     - 昨日任务完成率
     - 断签天数
   - Mock 建议已支持断签回归模式：连续多天未记录时优先生成轻量恢复建议。
   - Mock 建议会结合健康目标生成更贴合当前目标的文案。

3. 缓存层
   - 新增 `CacheService`。
   - 支持配置 `REDIS_URL` 使用 Redis。
   - 未配置 Redis 或 Redis 不可用时，自动使用进程内内存缓存兜底。
   - 每日建议按 `advice:daily:{userId}:{date}` 缓存，避免同日重复调用 AI。
   - 新增配置项：
     - `REDIS_URL`
     - `CACHE_TTL_SECONDS`
   - `requirements.txt` 已新增 `redis==5.2.1`。

4. 后台维护任务服务
   - 新增 `MaintenanceService`。
   - 支持归档历史任务。
   - 支持批量生成周健康总结。
   - 支持预生成每日建议，并同步写入缓存、建议历史和每日任务表。
   - 预生成任务时会使用任务 upsert 逻辑，避免重复任务。

5. 后台维护接口
   - 新增受 JWT 保护的管理接口：
     - `POST /api/admin/jobs/archive-tasks`
     - `POST /api/admin/jobs/weekly-summary`
     - `POST /api/admin/jobs/pre-generate-advice`
     - `POST /api/admin/jobs/run-daily`
   - 这些接口目前可手动调用，后续可直接接入 Celery、APScheduler 或系统 cron。

6. 文档同步
   - `backend/README.md` 已补充健康总结接口、后台任务接口、Redis 缓存说明。
   - 本文档已同步第二轮实现内容。
